# 台本の 書き方の 決まり

根拠は ( ) の 中。数字は 2026-11-14 に 台本と src/ を 調べて 決めた。

## 字と 空白

- **かな と カタカナ だけ で 書く。漢字は 使わない。**（イベントの 台詞に 漢字は ない。灯台1Fの「気」「元気」は 2026-11-15 に かなに 直した。のこるのは デバッグ・あずかりやの 料金「円」。charmap_kanji.txt で 字は 出せるが、台本の 見た目が そろわない）
- **文節ごとに 半角の 空白 を 1つ。**（いまの 台本の かなの 行は、全角の 空白を ふくまない ラベルが 約 3万8千行、ふくむ ラベルが 約 700行。ROM では どちらも 同じ 字 00 で、幅も 同じ 8px。新しい イベントは ぜんぶ 半角）
  - 1つの ラベルの 中で 半角と 全角を まぜない。全角の 台本（もとの FR の 文、Route2 など）を 直す ときは、その ラベルの 中は 全角に あわせて よい
- 句読点「、」「。」は ふつう 使わない。区切りは 空白、文の 終わりは 行の 終わりか ！ ？ …
- 「…」は 1つが ふつう。間を 長く とる 人（ミオ・したっぱの 負け）は「……」
- ！ ？ は 全角でも 半角でも 同じ 字（charmap で AB / AC）。ラベルの 中で そろえる。新しい 台詞は 全角が 多い
- 数は 半角の 数字（3びき、50にん）
- **charmap に ない 字**: （ ） ～ 〜 ― — ♪ ★ → １ など。かっこは「」を 使う（メモ pending-decisions「全角の （ ） は ない」）。ためすには scripts/check_event_text.py

## 1行の 長さ

| 窓 | こえると はみ出す | 目安 | 根拠 |
|---|---|---|---|
| ふつうの 窓（msgbox） | 27字 | **21字まで**（新しく 書くなら 16〜18字が 読みやすい） | 窓は 幅 27 タイル、日本語の 字は 空白も ふくめ どれも 8px（src/menu.c の sStandardTextBox_WindowTemplates、src/text.c の GetJapaneseGlyphWidth）。いまの 台本の 行は 21字 までが ほとんど（22字 いじょうは 1% 未満） |
| 電話（pokenavcall） | 24字 | **20字まで** | 窓は 幅 28 タイルだが、顔の 絵の 分 32px あけて 書く（src/match_call.c の sMatchCallTextWindow と printerTemplate.x = 32） |

- 置きかえ文字の 字数: {PLAYER} {RIVAL} は ふだん 5字・いちばん 長くて 7字（PLAYER_NAME_LENGTH 7）、{KUN} は「くん」2字か「ちゃん」3字。7字で こえないか 道具が 見る
- 名札「名前『」の 部分は 名前の 窓に うつるので、1行目の 長さに 入れない

## 改行の 記号

- 窓は **2行**。`\n` は 1行目 → 2行目。
- 3行目から 先は `\l`（上に 送る）か `\p`（窓を 消して 次の ページ）。**1ページに `\n` を 2つ 書かない**（3行目が 窓の 外に 出る）
- 新しい 台詞は「2行 書いたら `\p`」を 基本に する。`\l` は 長い 説明を つなぐ ときだけ（もとの FR・エメラルドの 文に 多い）
- 文の 終わりは かならず `$`
- 1つの ラベルは `.string "…\n"` `.string "…\p"` `.string "…$"` と 1行ずつ 書く

```
Route9_Text_NanamiBye::
	.string "ナナミ『よかったね フリーザー\p"
	.string "わたしは この ひとを\n"
	.string "つれて いくね\p"
	.string "{PLAYER}{KUN} きを つけてね$"
```

## 名札

仕組みは src/field_speaker_prefix.c（ConvertSpeakerPrefixesToNamebox）。

- 書き方は **`名前『`**。名前は 名前の 窓に うつり、本文から 消える
- **閉じの `』` は 書かない。** 名札と 同じ 行に `』` が あると「ボックス『…』が」の ような 題名と みなされ、名札に ならない（IsClosedOnSameLine）
- 名札が きくのは **ページの 頭だけ**（文の 頭 と `\p` の あと）。`\n` や `\l` の あとに 書いても 名札に ならず、そのまま 字が 出る
- 名前は 8字まで、空白なし（SPEAKER_NAME_MAX_GLYPHS）。`{RIVAL}『` は 使える
- ページごとに 名札を 書く。話し手が かわる ページには かならず 新しい 名札
- 名札を 書かない ページは、前の ページの 名札の まま
- 名札を 書かない 台詞（町の 人・勝負の まえの トレーナー）は、話しかけた 人の 見た目から 名札が 自動で 出る（名前の ある 人 → トレーナーの 種類 → 役目 → 呼び名）。看板は「かんばん」、黒い 字の 地の文は「システム」
- 名前の ある 人（sKnownSpeakers: ナナミ・ミオ・{RIVAL}・オーキド・シルバー・アポロ・ランス・アテナ・マツバ・ジムリーダーなど）が まだ 画面に いない ときは、名札が 自動で「？？？」に なる。電話では 名前の まま
  - 姿を 見せる まえに 呼ぶ 声は、わかりやすく `？？？『{PLAYER}{KUN}！$` と 書いて よい（Route9 の NanamiCalls）
- 名札を 出さない 人（シルバーなど）は スクリプトで `setspeaker ラベル`（名前だけの .string）
- 話し手の 色は スクリプトで `textcolor NPC_TEXT_COLOR_FEMALE / MALE / NEUTRAL`（地の文は NEUTRAL）

## ポケモンの 鳴き声

- **「」で 囲まない。**（メモ mon-lines-no-brackets）
- 名札を 付けるなら `ビクティニ『ティニッ！$`。`『` は 名札の 印で、かっこでは ない
- 町に いる ポケモンは 名札も 書かずに `ブイブイッ!$` で よい（見た目から 名札が 出る）
- 鳴き声の まえに スクリプトで `playmoncry SPECIES_…` `waitmoncry`

## 地の文（システムの 文）

- 名札なし、`textcolor NPC_TEXT_COLOR_NEUTRAL`
- 型: `{PLAYER}は フリーザーを\nてに いれた！$` / `{PLAYER}は マツバから\n{STR_VAR_1}を もらった！$` / `ランスは あなぬけのヒモで\nきえて しまった$`
- 見た ことを 1〜2行で。気持ちを 書かない（「くろい オーラが\nとびちって きえた！」）
- ようすの 文は「…」で 終えて よい（「フリーザーが もがいている…」）

## 電話（pokenavcall）

- スクリプト: `pokenavcall ラベル` → `waitmessage` → `closemessage`。家の 中では 電話が できない
- 文は 名札つきで 書く: `ナナミ『もしもし {PLAYER}{KUN}？\n…`（CeruleanCity_House2 の NanamiShadowCall）。名札なしで「… あ {PLAYER}{KUN}？\nナナミだよ」と 名のる 形も ある（nanami_dates.inc）
- 1行 20字まで（上の 表）。3ページ 前後
- エントリーコールの 定まった 電話は data/text/match_call.inc の MatchCall_Text_*（道具は ラベル名で 電話と みなす）

## 台詞の 中身

- 短く。1ページ 1〜2行。1回の 話しかけで 3ページを こえたら けずれないか 見る
- 説明しない。仕組み（「マスターボールと おなじ ちから」）や 事情の ぜんぶを しゃべらせない。わかって いる ことの 一部だけ、行動と いっしょに
- 人物ごとの 声で（characters/*.toml）。全員が 同じ 口調に ならない ように
- 元の ゲームの 台詞を そのまま 写さない（BW・HGSS の 台詞は 公開リポジトリに 入れない）。場面の 流れだけ かりる
- 悪役の「こども」「ガキ」は わざと。直さない
- 恋人の 場面は におわせる 程度
